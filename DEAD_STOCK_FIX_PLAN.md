## Приоритет 1: Критические (блокируют использование)

### 1.1 Синхронизация остатков (stock quantity = 0)

**Проблема:** `shopProduct.quantity` = 0 для всех товаров. Без остатков `totalFrozenCost` считается как цена за единицу, а не `qty × unitCost`.

**Причина:** Функция `updateProductsShope` (cron каждые 25 мин) обновляет товары из API Эвотор, но не запрашивает остатки. Либо `syncStock` не вызывается.

**Решение:**
1. Проверить `syncStock` в `server.ts` — есть ли вызов?
2. Добавить запрос остатков в `updateProductsShope` или отдельный `syncStock` cron
3. Использовать `c.var.evotor.getStockByGroup()` для получения актуальных остатков

**Файлы:**
- `packages/backend/src/sync/cron.ts` — `syncStock` / `updateProductsShope`
- `packages/backend/server.ts` — cron setup

**Оценка:** 1 час

## Приоритет 2: Улучшения (не блокируют)

### 2.1 daysWithoutSales = -1 для сегодняшних продаж

**Проблема:** Для товаров, проданных сегодня, `daysWithoutSales = -1`.

**Причина:** В `refreshDeadStockCache` используется `Date.now()` (UTC), а `lastSaleDate` хранится как `YYYY-MM-DD`. Разница во времени может давать отрицательное значение.

**Решение:** Использовать `Math.max(0, days)` при вычислении.

**Файлы:**
- `packages/backend/src/sync/db.ts` — `refreshDeadStockCache`

**Оценка:** 15 минут

---

### 2.2 POST «Wider 999» тест не проходит

**Проблема:** Тест ожидает, что при расширении периода (30д → всё время) количество товаров с `days=999` уменьшится.

**Причина:** POST теперь использует кэш (90-дневное окно), а не сканирует документы за произвольный период. Период `startDate/endDate` больше не влияет на `lastSaleDate`.

**Решение (опционально):**
- Добавить параметр `useCache=true/false` в POST
- При `useCache=false` — сканировать документы за полный период
- При `useCache=true` (по умолчанию) — использовать кэш

**Файлы:**
- `packages/backend/src/api.ts` — `POST /api/dead-stocks/data`

**Оценка:** 1 час (опционально)

---

### 2.3 Дедупликация товаров по имени

**Проблема:** UUID товара разный в разных магазинах для одного и того же товара. Кэш и POST могут дублировать записи.

**Решение:** Использовать `name|shopId` как альтернативный ключ (уже частично реализовано в `refreshDeadStockCache`).

**Файлы:**
- `packages/backend/src/sync/db.ts`
- `packages/backend/src/api.ts`

**Оценка:** 30 минут
